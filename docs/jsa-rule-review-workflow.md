# JSA专业规则审核工作流

## 审核入口

可视化审核页：`dashboard/jsa-rule-review.html`

页面从`data/jsa-rules.json`读取候选规则，但不会直接修改规则库或发布生产规则。

## 产品负责人操作

1. 填写审核人和审核日期；
2. 逐条检查适用场景、触发条件、风险提示、原因和建议行动；
3. 为每条规则选择：
   - `approved`：专业内容认可，可进入内部测试；
   - `needs_revision`：需要修改，必须填写修改意见；
   - `rejected`：不采用，必须填写拒绝原因；
   - `pending`：暂不决定；
4. 批准规则前补充可追溯的专业来源或参考标准；
5. 点击“下载审核结果”，将JSON文件交给Codex处理。

审核草稿仅保存在当前浏览器的`localStorage`中，不包含网站管理凭据、激活码或JSA作业内容。

## Codex后续操作

收到审核结果后，Codex负责：

1. 校验规则库版本、规则编号和审核字段；
2. 根据审核意见修改规则；
3. 将产品负责人批准结果写入结构化规则库；
4. 关联产品负责人提供的脱敏黄金案例；
5. 执行规则引擎、治理门槛和黄金案例回归测试；
6. 更新发布记录并提交独立commit；
7. 报告测试结果和仍未满足的上线条件。

## 状态边界

审核页中的“批准”只表示产品负责人认可专业内容，可以进入内部测试，不表示：

- 规则已经上线；
- 作业安全；
- 符合法规；
- 风险已经可接受；
- JSA可以批准。

生产环境仍只允许加载同时满足专业审核、黄金案例覆盖和回归测试要求的规则。
