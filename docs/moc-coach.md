# MOC 变更管理教练

首版入口：`/tools/moc-coach.html`。面向 EHS、工艺、设备和生产人员，辅助完成单条变更从边界判断、评估、行动与线下审批记录到投用检查和验证关闭的草案。全部单记录功能、安全提示和导出免费，不新增账户或会员能力门禁。

## 本地数据与专业边界

- 数据保存在当前浏览器；业务字段不发送到网站服务端。用户应使用岗位代称和脱敏描述，并定期导出 JSON 备份。
- JSON 用于备份和恢复；行动清单、台账通过 CSV 导出；报告通过浏览器打印或另存 PDF。切换浏览器或清理浏览器数据不会自动恢复记录。
- 线下批准结果由用户录入；姓名文本、日期及本地审计轨迹不构成身份验证、电子签章或不可篡改存证。
- 风险矩阵与等级建议是演示配置。工具不能认定企业已经合规、安全投用或完成正式审批，也不替代专业风险评估、工程审查或 PSSR。
- 导入记录仍须经过结构与规则检查。导入状态、历史批准或“已完成”文字不能取代当前版本的门禁与现场证据。

MOC 页面在 `body` 设置 `data-site-shell-features="local"`。公共 `js/site-shell.js` 仍渲染并初始化导航，但跳过共享统计、会员会话、会员 UI 和反馈对话框的启动；也不调用页面中已经存在的会员状态渲染。会员链接静态显示“会员入口”，反馈链接直接进入 `/feedback.html`，不携带记录内容或查询参数。页面自身仍须仅加载可信的本地代码，并使用与本地处理模式一致的 CSP；该标记不负责撤销其他代码已经发出的请求。

### 应急 48 小时

AQ/T 3034-2022 第 4.15.3.5 给出紧急变更实施后尽快按临时变更流程补办手续、一般不超过 48 h 的要求；不是免除实施前控制和授权的宽限期。显示提醒时应同时展示实际实施时间与补办情况，不能用倒计时证明风险已经受控。不要将 OSHA 第 (m) 节的事故调查 48 小时要求混作 MOC 补办依据。

### PSSR

AQ/T 3034-2022 第 4.8.6 明确新建项目正式投料前开展开车前安全审查。OSHA 第 1910.119(i) 节适用于其管辖范围内的新设施，以及改变程度足以要求更新过程安全信息的改造设施；MOC 的覆盖范围更广。[OSHA 官方解释](https://www.osha.gov/laws-regs/standardinterpretations/1996-01-11)说明细微改造不必机械等同于 PSSR。

因此，本工具对工艺、设备、仪表和安全关键功能等变更默认建议 PSSR，最终依据适用要求与企业制度确认；纯文控或组织变更不机械触发，若影响人员能力、岗位配置、应急或操作准备仍需人工判断。被确认必需的 PSSR 未通过时，不应放行投用。

## 规则维护与验收重点

以下是本模块的验收契约，应同时覆盖正常录入、后续编辑和备份导入：

1. 同类替换输出为“可能属于同类替换，仍需授权人确认”“建议进入 MOC”“信息不足，需要专业人员判断”三态；未知项、缺少依据或关键变化不能自动通过。
2. 重要变更触发理由可追溯。企业配置可以明确角色与阈值，不能将机器建议展示为最终审批结论。
3. 残余风险缺失不进入审批准备；极高风险不能只填接受人绕过；投用所依据的控制措施须已落实并验证。
4. 门禁校验覆盖审批、实施、投用、关闭。安全关键遗留项不能通过改为“投用后完成”绕过；非关键遗留项须有书面依据、责任人、期限及批准记录。
5. 批准与记录版本关联。范围、方案及关键控制改变时重新评审，审计注明失效原因；如需完整历史版本，在修改前导出 JSON。
6. 临时变更到期重新检查，不自动关闭或通过修改到期日直接延长。转永久需关联新的评审和授权。
7. 导出也显示当前阻断项与本地记录性质。处理 HTML、CSV 和导入对象时分别防止脚本注入、公式注入及结构污染。

多记录看板、企业模板、企业矩阵、提醒提前量和审批权限可以作为后续配置增强；当前不预埋无法兑现的付费门禁，不把安全结论和门禁检查藏在会员功能后面。团队审批、电子签名、跨设备同步及附件云存储需另行设计真实身份和权限体系。

## 测试与交付检查

入口与隐私模式的自动验证：

```sh
node --test tests/moc-integration.test.mjs tests/navigation-contract.test.mjs tests/homepage-astra.test.mjs tests/membership-feedback.test.mjs
```

`moc-integration.test.mjs` 在隔离运行环境实际执行公共 shell 与资料索引脚本，验证本地模式不加载共享网络特性、默认模式保持原行为、MOC 可以搜索找到且不改变资料目录。业务规则由 MOC 引擎测试覆盖。

发布前还应运行相应 MOC 规则/导出测试、全站静态链接检查和敏感信息扫描，并在浏览器核验：新建与恢复、阻断状态、到期、PSSR、版本重审、恶意输入、打印、CSV、360–390 px 屏幕及键盘操作。不得将未执行的检查报告为通过。

静态页面或共享脚本变化时使用新缓存版本。同步到现有托管后，再核验线上 MOC 页面和所有静态配置/脚本均为本次内容、响应类型正确、入口可达；源码仓库修改本身不代表已上线。MOC 不需要新增业务 API、数据库、域名或托管服务。
