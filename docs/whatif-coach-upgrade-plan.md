## 评估与取舍

参考表的有用结构是：项目范围及团队 → 偏差提问 → 原因/后果 → 现有屏障 → 屏障弱化因素 → 建议与行动状态。评级采用可能性 A–F 与人员/环境/资产后果 1–5 的编码，而非简单相乘。网站旧版默认赋值及自动低残余风险不利于专业判断。

保留结构而重新实现交互和公式。不复用任何机构标识、原工作簿图片、作者属性或隐藏包数据；不把特定单位的频率、金额与环境量阈值移植成通用标准。正式界面不展示材料制作过程信息。原始工作簿不进入公开仓库或在线资产。

## 最小可用升级

1. 项目和节点：正常设计意图、边界、运行阶段、团队、资料与评估口径。
2. 生成问题：按工艺上下文推荐偏差问题，批量去重；一键生成原因、后果和建议的“待讨论”草案。
3. 逐项复核：只由用户确认适用性、现场屏障、有效性依据、弱化因素与失效后果。未评级保持待评估。
4. 行动与输出：负责人、期限、完成依据、效果与复核记录；预测不冒充实际复评。导出四表 Excel、打印/PDF 与 JSON 备份。

上限 20 个节点、80 个情景，每个文本字段 800 字。大范围或复杂过程应分批分析并采用适当的深入方法，而非靠问题数量证明覆盖完整。

## 专业与隐私边界

- 自动推荐是讨论线索，不是现场事实或穷尽清单；不自动接受风险、批准作业或判断法规符合性。
- 参考矩阵用文字和颜色同时表达讨论优先级，不提供“安全分”。正式口径不同时应在正式报告按批准标准复核。
- 不调用云端生成模型，不上传填写内容，不加载第三方追踪。数据仅显式保存本机或下载；共享设备应避免保存敏感资料。
- 旧草稿原样保留；旧数字评分记录于备注，重新按新版口径评估，不做未经验证的映射。

这些是方法参考，具有各自适用地域、时间和场景边界，不构成对中国法规的自动符合性认定。技术测试不是现场专业验证。

## 发布控制

工具源代码、脚本、样式和导出库只进入私有 Worker 资产，不能同步到公开 OSS 或 GitHub。公开改动仅为风险分析页的入口说明和产品记录。

发布前重新确认线上 Worker 版本与当前配置，保存回退版本；不改 DNS、证书、主站托管、会员政策、D1 表结构或激活数据。部署后核实匿名/失效会员无法读取 HTML 和资源，有效会员可访问工具和导出；再同步公开入口介绍到 OSS 并校验哈希。任一闸门失败不宣布上线。
