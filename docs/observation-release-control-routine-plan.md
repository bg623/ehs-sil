# EHS-SIL 观察与发布控制 Routine Work Plan

版本：V1.0

建立日期：2026-08-25

负责人：产品负责人 / Codex

适用范围：`ehs-sil.com`、GitHub Pages、会员 Worker / D1，以及与网站生产发布直接相关的指标和记录

## 1. 任务定位

本任务固定作为：

> EHS-SIL 网站的观察、验收、发布控制与复盘工作台。

本任务负责确保：

1. 生产网站持续可访问；
2. 首页、公共导航、JSA、会员激活和关键工具没有可复现回归；
3. 每次发布都有明确范围、测试证据、生产提交和回退依据；
4. 观察数据按固定口径记录，不把内部测试、示例或推测当成真实用户证据；
5. 只有在观察和复盘支持时才进入下一阶段。

## 2. 职责边界

### 本任务可以做

- 检查 Git、GitHub Pages、域名、关键生产页面和构建状态；
- 检查公共导航、移动端结构、站内链接和关键工具入口；
- 运行自动化回归、Worker 测试和只读 D1 汇总；
- 审计埋点结构、事件版本和数据可读性；
- 判断发布是否影响当前观察窗口；
- 记录 P0 / P1 / P2 问题并决定热修复、观察或转入独立开发任务；
- 更新观察日志、发布记录、DMAIC 日志和产品指标；
- 对已批准的小范围修复进行测试和发布。

### 本任务不做

- 不在没有验证问题的情况下增加新功能；
- 不直接开发新的 JSA、LFI、培训矩阵、法规或会员产品版本；
- 不把内容发布、SEO流量、自动化访问或内部演示解释为产品成功；
- 不在观察窗口中途随意修改核心入口或统计口径；
- 不读取、提交或公开激活码、会话令牌、购买者明细和用户输入；
- 不把不同会员状态、不同工具或不同来源渠道的数据混合统计。

新功能需求统一转入独立任务和独立分支；完成独立验收后，再回到本任务执行发布闸门和观察登记。

## 3. 固定工作状态

任务只使用以下五种状态：

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| `MONITORING` | 正常观察 | 只读检查、记录和固定检查点 |
| `RELEASE_REVIEW` | 有待发布改动 | 范围审计、测试、风险判断和发布确认 |
| `HOTFIX` | 出现 P0 / P1 回归 | 最小修复、专项测试、立即验证和记录 |
| `RETROSPECTIVE` | 到达 Day 14 或阶段复盘 | 数据汇总、结论和下一步决策 |
| `BLOCKED` | 缺少权限、数据或产品负责人决定 | 记录证据和所需输入，不猜测结论 |

默认状态为 `MONITORING`。

## 4. Routine Work 节奏

| 频率 / 触发条件 | 固定检查 | 输出 |
| --- | --- | --- |
| 每次生产发布后 | 提交范围、Pages构建、关键页面、哈希/版本、回归测试 | 发布登记；判断是否重置观察窗口 |
| 每日轻量检查 | Pages状态、首页、工具索引、JSA、会员激活、法规识别 | 仅异常时写记录；正常情况不制造无意义提交 |
| Day 0 | 固定生产基线、全量回归、线上一致性 | 建立观察窗口 |
| Day 1 | 页面错误、导航、会员接口、数据可读性 | Day 1 记录 |
| Day 3 | 事件完整性、明显退出异常、P0/P1回归 | Day 3 记录 |
| Day 7 | 首次漏斗趋势、分组样本量、数据质量 | 中期 Review，不提前定结论 |
| Day 14 | 同周期对比、真实反馈、性能和稳定性 | 固定窗口汇总 |
| 正式复盘 | 继续、单点优化、回滚或延长观察 | 产品负责人决策记录 |
| 每月 | 激活码、有效会话、撤销/过期、权限和备份可读性 | 会员运营与安全检查 |
| 每季度 | 规则来源、法规来源、隐私边界、会员文案和依赖 | 治理 Review |

## 5. 每次发布的强制闸门

按以下顺序执行：

1. **保护现场**
   - 检查当前工作目录和 `git status`；
   - 不覆盖、暂存或丢弃其他任务的未提交修改；
   - 必要时使用独立工作树。
2. **确认远端**
   - 获取 GitHub `main` 最新提交；
   - 比较本次改动与生产头；
   - 发现并发更新时重新同步，不强制推送。
3. **分类改动**
   - 核心漏斗改动；
   - 工具独立改动；
   - 内容 / SEO 改动；
   - 安全或兼容性修复；
   - 纯文档改动。
4. **验证**
   - `git diff --check`；
   - 全量或风险相称的自动化测试；
   - 静态链接检查；
   - 关键生产页面 HTTP 和内容一致性；
   - 涉及会员时检查匿名会话接口、Worker 测试和只读 D1 健康状态。
5. **发布**
   - 只提交本次明确范围内的文件；
   - 使用非强制快进更新；
   - 确认 GitHub Pages 状态为 `built`；
   - 记录生产提交 SHA。
6. **发布后控制**
   - 复核关键页面；
   - 更新观察日志和发布记录；
   - 明确是否继续原窗口、重置窗口或进入热修复。

## 6. 观察窗口重置规则

以下变化上线后必须停止原窗口，并从新生产提交重新计算 14 天：

- 首页首屏或主 CTA；
- 公共导航结构或关键入口；
- JSA 主入口、完成流程或导出入口；
- 会员入口、激活流程或权益口径；
- 统一事件名称、事件版本、分母定义或关键埋点覆盖；
- 会显著改变用户到达来源或漏斗路径的其他改动。

以下变化通常不重置，但必须登记并单独分组：

- 不改变核心入口的文章和 SEO 内容；
- 法规来源修正；
- 某个独立工具内部版本升级；
- 不改变用户行为路径的安全、缓存或兼容性修复；
- 纯文档和测试改动。

无法确定时，按“可能影响”处理，由产品负责人决定；不得为了赶进度默认不重置。

## 7. 异常等级与响应

| 等级 | 示例 | 响应 |
| --- | --- | --- |
| P0 | 网站不可访问、激活服务中断、敏感信息泄露、严重越权 | 立即停止发布与观察，进入 `HOTFIX`，修复后重新建立基线 |
| P1 | 公共导航失效、核心工具无法完成、会员误拦截、导出失败 | 当日最小修复并专项回归；评估是否重置窗口 |
| P2 | 局部样式、低频文案、非核心兼容性问题 | 登记并进入下一次计划修复，不中断观察 |
| 数据缺口 | 百度漏斗不可读、PageSpeed超时、样本不足 | 标记缺失，不填估算值，不解释为零 |

## 8. 数据与隐私规则

- 真实会员数据按 `toolbox_member`、`legacy_vip`、过期和未知状态分开；
- JSA 示例模式和用户模式分开；
- LFI、培训矩阵、法规工具和 JSA 不混成一个产品漏斗；
- 自动化测试、Codex验收和内部访问不得计入真实用户指标；
- 不在公开仓库记录激活码、用户身份、令牌或精确运营明细；
- 激活成功率必须有成功与失败结果记录，不能用会话数除以限流次数估算；
- 没有百度统计后台导出时，只能确认事件契约，不能判断转化趋势；
- 真实工作采用、发现遗漏、购买和续费必须由真实反馈或权威服务端数据确认。

## 9. 固定记录文件

- `docs/stage-1-observation-log.md`：当前观察窗口和检查点；
- `docs/release-notes.md`：发布事实；
- `docs/dmaic-experiment-log.md`：假设、证据和决策；
- `docs/product-metrics.md`：指标定义和数据边界；
- 本文件：Routine Work 的长期操作规则。

同一事实只在一个文件中详细记录，其他文件引用简要结论，避免多处口径漂移。

## 10. 职责划分

### Codex

- 执行只读审计、测试、生产一致性检查和数据汇总；
- 识别并保护并发修改；
- 更新观察、发布、DMAIC和指标记录；
- 在明确授权范围内实施最小修复和部署；
- 不虚构真实用户行为、访谈、付费意愿或数据结论。

### 产品负责人

- 决定是否批准核心入口、会员口径和统计口径变更；
- 提供或导出百度统计、真实用户反馈和分组信息；
- 决定观察期继续、重置、优化、回滚或进入下一阶段；
- 批准 P2 优化优先级和新功能立项。

## 13. 本任务的固定开场指令

以后在本任务继续工作时，使用以下约定：

> 继续 EHS-SIL 观察与发布控制。先检查独立观察工作树、远端主分支和生产状态，保留其他任务修改；按当前检查点执行，只记录真实证据，不开发未批准的新功能，不因内容或独立工具发布自动重置窗口。

阶段复盘完成后，本任务不结束，而是回到 `MONITORING`，继续承担发布闸门、月度会员检查和季度治理 Review。
