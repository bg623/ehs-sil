# 甲醇储罐泄漏—池火融合 V0.2.1

## 范围与来源

按项目负责人2026-11-25要求，将其提供的Kimi M01设备、液流、湿润液池及体积火焰算法融入现有工作台。原附件只读保留，不直接运行其中部署说明或迁移其独立UI。附件app独立构建/浏览器实测通过，7张参考图和6秒参考录屏已核对；GLB自包含但只含设备，没有火焰与事故逻辑。

采用同源程序化设备代码而非异步加载GLB，继续使用现有Three.js 0.181.2，无新增运行依赖、外部字体/贴图/模型请求。源码归档于 `js/scenario/kimi-m01/`，火焰场位于 `effects/m01-pool-fire.mjs`；资产清单记录各源文件SHA。Kimi代码来自用户提供的交付，仅声明本次集成授权，不虚构独立素材许可证。

## 成功迁入与适配

- 原页面、条件编辑、唯一播放时钟、暂停/重播/阶段/进度反拖及Orbit镜头继续使用；既有6等分阶段映射到Kimi的6个不等分视觉阶段，没有第二个永久动画循环。
- 储罐、平台护栏、梯子、人孔、法兰、阀轮、铭牌与围堰迁入。铭牌/液位反映当前条件，不固定显示30m³；下游短管与法兰采用真实内孔，泄漏锚点与模型出口一致。
- 供应商Y-up米制转换为ENU，再由已有转换映射Three。D/H与围堰L/W/H独立缩放，不改变用户工况。
- 原附件液池边缘越出围堰内缘约0.286m。融合保留用户半径，按完整不规则轮廓避让罐基础/围堰，不能安放时不启用M01；不缩小半径伪装满足条件。
- 液流前沿、飞沫、落点与湿池由统一进度驱动；火焰密度算法移入已有逐射线不透明深度截断的合成器，不迁入原单独火焰盒mesh。
- 共享几何/材质/纹理去重释放，InstancedMesh自行释放；镜头、模式与画质不触发工程分析任务。PNG使用相同场景/相机重新高分辨渲染，并带 `visualAdapter` 元数据。

## 不支持与回退

M01仅用于纯液态甲醇、立式储罐、阀后释放、池火、详细教学分镜且几何可安放的条件。混合物、其他物料、罐壁泄漏、卧罐、喷射火/闪火/VCE/受限空间及不可安放尺寸，继续原有通用模型或原机制教学，不把甲醇外观套给其他条件。

没有迁入Kimi独立页面、UI、独立时钟、硬编码工况、设备GLB下载、原未做深度截断的火焰mesh或外部工业环境。光照/环境仍沿用工作台，镜头和时间轴也有适配，因此不是对参考图逐像素复刻。

APP变为0.2.1；DATA仍scenario-data-0.2.0、SCHEMA仍1.1.0、MODEL仍0.1.0。capabilities仅appVersion元数据变化，工程开关/物性/registry/审核状态不变。工程结果仍null，不提供CFD、QRA、浓度、热辐射、超压或安全距离结论。
