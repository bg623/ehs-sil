# V0.1.1 视觉组件与资源核查

执行日期：2026-11-16，北京时间。环境：本机 macOS，Playwright 1.57.0，Headless Chromium 149.0.7827.55，软件渲染。以下是独立渲染组件的实际测试，不代表真实手机硬件、物理模型验证或生产发布通过。

## 实现与接口

`view-2d.mjs` 接收当前 `sceneSpec` 与纯采样 `frame`；没有可用分析结果也不会自动选择池火。六类事故使用独立机制图。池火详细俯视图来自设备、根阀、泄漏与液池锚点；物料名、显示模式和场景均来自当前输入。

`view-3d.mjs` 复用一个 renderer；无私有动画时钟，由主应用传入帧。`three/scene-components.mjs` 拆分储罐、接管与根阀、围堰/排液、液位示意及池火。设备签名变化才释放旧 assembly 并重建；换料、显示模式和阶段只改变材质/可见性/变换。

火焰为三层连续 Shader 面片，根部锚定预设液池，使用输入帧的 `noiseTime` 确定性采样。没有独立橙色火焰锥体，没有甲醇黑烟或火球。甲醇自然模式为弱淡蓝，辅助模式增强轮廓；两种都有常驻文字说明，不表示实测影像、热像或后果范围。

设备包含固定顶、加强圈、直梯、顶护栏、人孔、基础、阀门/阀轮和库存液位示意。未知质量到体积转换不会在渲染器中补密度。五种镜头为总览、储罐、泄漏点、液池、俯视；设备变化会更新相机边界，普通换料不跳镜头。

## 整页紧凑视口问题与修复

整页旧构建在 746×390 像素视口、增强模式、进度 0.68 时，根阀、泄漏点与液池三个不透明标签正好遮住弱淡蓝火焰主体。已在独立浏览器上下文重现：进度确为 0.68、阶段为“措施作用点”，当前甲醇/池火/增强模式正确；只对标签 DOM 设置 `visibility:hidden`、不调用 WebGL 重绘，火焰即可见。因此不是丢失 `fireVisible`、Shader 编译失败或 GPU 首帧问题。

修复仅为展示：根据当前相机投影的火焰教学轮廓区域避让标签，用细引导线连回设备锚点；不修改甲醇颜色、透明度、高度或烟气。液池近景同时抬高视线并略后退，保证完整教学火焰顶端入镜。避让计算不创建几何或材质，不添加动画时钟。修复后再次执行上述全部渲染回归，实际计数与资源释放结果保持一致。

修复的组件截图保存在本工作树 `test-results/scenario-v011/flame-label-fixed-746.png`、`flame-label-fixed-330.png`、`flame-label-fixed-960.png`；修复前定位截图以 `flame-inspect-` 开头。此处仅报告组件级验证，整页最新版仍须由主浏览器验收重建后重新采图。

整页响应式、输入事务、迁移、导出、WebGL/资源失败降级、CSP 和网络隐私由主浏览器验收负责；这里不将组件结果替代整页或生产验收。真实手机性能、人群首次使用试验及物理模型验证均未在本组件测试中执行。
