# 5Why + 鱼骨图专业教练升级方案

2026-09-25。范围：原免费入口 `tools/rca-tool.html`，相关工具卡与站点地图。保持首页布局、会员权益、独立事故调查教练、DNS、OSS 托管与 VIP Worker 不变。

## 现状评估

旧版用六类原因卡片代替鱼骨图，限制追问最多五层，并提示“根因基本明确”；无法支持多路径假设、证据与反证、原因到行动的追溯。标为 Excel 的下载实际是 CSV。初始化脚本还引用不存在的计数元素。这些问题不能只靠视觉美化解决。

## 方法依据与取舍

2026-09-24 核对以下官方方法资料；没有机构认证或专业审查完成的声明。

- [ASQ 五问法](https://asq.org/quality-resources/five-whys)：追问可以少于或多于五次。改为可分支的连续追问，以证据而非层数决定调查是否充分。
- [ASQ 鱼骨图](https://asq.org/quality-resources/fishbone)：组织可能原因，不证明因果。保留常见六类并增加管理与组织、待分类区，不称为“国际统一八类标准”。
- [OSHA 事件调查](https://www.osha.gov/incident-investigation)：关注系统性原因，不止于个人失误。遇到“粗心、违规”等标签时继续提示工作条件和组织因素。
- [IHI RCA²](https://www.ihi.org/library/tools/rca2-improving-root-cause-analyses-and-actions-prevent-harm)：原因分析需要落实到可持续行动和效果验证。借鉴其系统改进理念，不把医疗领域框架当作工业法定标准或声称官方背书。
- [NIOSH 控制层级](https://www.cdc.gov/niosh/hierarchy-of-controls/about/index.html)：提示评估消除、替代和工程控制，不能自动判定某项措施有效。

## 四步最小工作流

1. 描述问题：事实、预期偏差、时间地点与临时处置。
2. 整理原因：四种关键词情景提供调查问题，批量按行输入并去重、建议分类；实时 SVG 鱼骨图和完整节点列表。
3. 追问验证：继续追问、平行分支、变更上层节点；记录证据、来源、反证、验证计划及复核人代号。
4. 行动与导出：未核实原因生成取证草案，具备支持记录的原因提供改进方向，均不覆盖已有行动。行动负责人、期限、判据和控制类型由调查组补全；实施与效果验证分开记录。

自动化是本地确定性关键词和规则，不调用在线 AI，不生成未经用户提供的事实、日期、责任人、证据或根因。模糊分类保留待分类。支持“待验证、证据支持、已排除”人工状态，同时显示证据缺口，不用绿色得分或完成百分比替代判断。

## 输出与隐私

- 标准 XLSX：分析概览、原因与证据、行动与验证、复核清单四表；文字以字面值写入，不执行用户公式。日期保持日期类型，缺失保留空白。
- 全节点 SVG、网页预览与浏览器打印/PDF；概览每类仅展示前两条并明确提示省略，完整内容在节点列表、Excel 与 SVG。
- JSON 完整备份/恢复；文件未加密，导出前提醒检查信息。
- 不上传填写内容、不接入遥测、不自动保存。只有用户点击才写入新本机键 `ehs_sil_rca_v2`，共享设备优先下载备份。
- 旧键 `ehs_sil_rca` 仅在用户点击恢复时读取，不覆盖、不删除；迁入原因全部待验证。恢复失败保持原有内容。
- 每份底稿最多 80 个原因、80 项行动，每个字段 800 字，备份最大 2 MB。复杂/高潜事件需跨专业调查组，另有完整事故调查工具入口。

## 验收与发布控制

软件回归覆盖超过五层、多分支、循环与悬空引用、删除后 ID 不复用、建议幂等、证据/排除依据缺口、行动效果缺口、注入文本、坏备份与旧草稿迁移。浏览器在 1440 / 390 / 320 像素测试。Excel 用独立解析及表格渲染检查。

发布以 GitHub 审查分支和测试树为准；仅上传本轮九个公开对象到现有 OSS，先比对旧对象与基线，备份后上传，最后验证公网哈希及 VIP 会话健康。发现生产漂移即停止，不能直接覆盖。回退恢复备份的旧页面、工具卡、站点地图；新增静态资源可以保留，未使用时没有业务作用。

软件测试不等于专家审定或真实用户验证。下一轮由产品负责人邀请用户验证：能否从已有线索完成有证据引用的原因与行动底稿；先收集退出点、所用时长和真实工作采用反馈，再决定是否增加 AI 或跨工具数据联动。
