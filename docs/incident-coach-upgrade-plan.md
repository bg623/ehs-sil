# 事故调查与 LFI 专业教练升级评估

日期：2026-09-21。依据产品负责人本次建议与当前代码核对。

## 评估结论

采用一个调查入口和共享事件数据，优先打通事实、屏障、原因、措施与学习。现有 LFI 入口为介绍页，旧演示为固定案例；5Why、Apollo RCA、Tripod Beta 仍是独立页面。现阶段不能宣称已有数据互通。

专业依据：HSE HSG245 将信息收集、分析、控制措施和行动计划组织为调查流程；OSHA 强调管理者与员工参与、超越表面归责；NIOSH 控制层级用于选择控制方式，不是个案安全评分。Tripod 官方资料强调事件、屏障和组织因素，正式应用涉及专门培训。

- https://www.hse.gov.uk/pubns/books/hsg245.htm
- https://www.osha.gov/incident-investigation
- https://www.cdc.gov/niosh/hierarchy-of-controls/about/index.html
- https://tripod.energyinst.org/beta

以上是方法参考，不把境外报告制度作为中国法定报告判断。核对日期 2026-09-21。

## 需要修正的建议

1. 快速、标准、深度是本站内部调查资源建议，不是事故法定等级，也不把“无伤害”直接归为低风险。未知潜在后果须进一步核实。
2. 不以证据数量自动判真；用户记录确认状态与依据，冲突不能被数量覆盖。
3. 控制层级不计算数值分数。工程措施也需适用性、维护与效果验证；处罚不能单独算风险控制。
4. 首版不自动识别人名或承诺自动去除隐私。仅当前页面内存，不默认浏览器长期保存；本地 JSON 备份也没有加密，需自行保管。
5. 保留现有会员高级工具与原 URL；不复制受保护源码到公开站点，不改变会员价格或权益。新基本工作流免费。建议中新增的会员分层需另行确认。
6. 不以更换名称代替知识产权审核。Apollo / Tripod 仅保留已有入口与方法参考，不声称获官方认证或完成授权审核。

## 本轮 V0.2 基本工作台

- 八步：事件概况、深度与策划、证据、时间线、屏障、原因、措施、验证与学习。
- 一个事件、稳定记录编号与跨步骤关联；原因按七个维度整理，可建立多条追问链，不强迫五问或单一根因。
- 方法建议及现场检查、访谈提示；人工决定深度。
- 提示待核实证据、无证据结论、孤立屏障/原因、缺少措施、仅依赖管理/PPE、措施完成与有效性混淆。
- 本地生成调查底稿、LFI 学习卡片、Excel、JSON 备份恢复、浏览器打印；不上传附件，不调用 AI 或业务后端，不发送填写内容。
- 首页只调整“事故与学习”相关入口，保留其他模块与旧工具。

## 后续顺序

V0.3：先用实际使用反馈验证八步是否易懂、关联是否有效，再考虑事件与因果关系图 ECFC、人因和程序差异分析、长期效果验证记录。

V0.4：在会员服务端权限、方法授权及迁移协议明确后，再做高级原因—结果图、Tripod 数据联动、多案例台账和重复事件分析。不开发企业事故云端系统。

## 验收与数据口径

技术验收覆盖空白/冲突/未知、高潜建议、悬空关联、原因环、措施验证、恶意备份、脚本与公式注入、导出恢复一致性、手机键盘与布局。测试案例均为合成，不代表专家结论或真实调查。

不在填写页加载分析或会员脚本。由产品负责人收集自愿反馈：能否从证据连接到措施、是否用于工作、是否再次使用。没有真实用户数据前，不宣称提升调查质量或降低事故率。

## 旧安全契约

2026-08 的多租户与后端契约继续冻结，不部署真实事故服务。本次用户明确要求本地优先的个人工具，因此更新公开入口的旧“不可输入”测试为“无网络采集、无自动持久化、无附件上传”，不放宽后端安全测试。
