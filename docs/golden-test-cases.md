# JSA黄金测试案例

数据文件：`tests/fixtures/jsa-golden-cases.json`

## 当前状态

- 已建立20个案例槽位；
- 已收到并技术脱敏5份真实JSA样本；
- 5个案例为工作簿级综合案例，15个案例按原表步骤范围拆分，均可追溯到真实样本；
- 20个案例均由Codex AI专业审核在产品负责人明确授权下确认并设为`approved`；
- 20个案例已通过正向和禁止触发规则回归测试，达到最低案例集要求；
- 不得将开发者示例或虚构场景标记为黄金案例。

技术脱敏包括人员、组织、区域、设备位号、日期、联系方式、嵌入图片、隐藏名称和文档元数据；原文件不覆盖，脱敏工作簿不进入公开网站仓库。

审核人统一记录为“Codex AI专业审核（产品负责人授权）”。这表示产品负责人授权AI完成结构化专业复核，不冒充独立人类注册专家或现场签字人员，也不构成作业批准、法规符合性或风险可接受性结论。

## 每个案例必须定义

- 输入场景；
- 预期触发规则；
- 不应触发规则；
- 关键风险遗漏；
- 专家确认结果；
- 脱敏样本引用；
- 审核人；
- 审核日期。

## 启用流程

1. 产品负责人提供原始样本；
2. Codex生成脱敏副本并完成反向泄漏扫描与逐页视觉复核；
3. Codex提出触发规则、不触发规则和关键遗漏候选；
4. 产品负责人逐项确认或修改预期结果；
5. 将案例状态改为`approved`；
6. 执行回归测试；
7. 规则或逻辑修改后再次执行全部已批准案例。

已批准的20个案例只计入内部规则回归，不计入真实用户效果、转化或北极星指标。规则仍需产品负责人最终上线批准后才能进入生产加载。
