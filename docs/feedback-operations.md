# 用户反馈接收与处理

版本：1.0｜2026-09-06

## 用户入口与数据边界

公开入口为 `/feedback.html`、全站页头/页脚及工具标题附近的“反馈此工具”。法规识别与培训矩阵的结果链接可带入工具 ID、公开条目 ID、工具版本和数据版本。表单不会自动读取企业画像、岗位结果、事故信息、剪贴板、Cookie、激活码或整个本地存储。

用户只需选择反馈类型并填写 10–2000 字问题描述。昵称与联系方式均可选；只有主动勾选需要回复时才要求微信或邮箱。联系信息仅用于该条反馈的人工跟进。

## 服务端与权限

- `POST https://vip-api.ehs-sil.com/api/feedback`：游客与会员均可提交；24 KiB 请求上限、字段长度和枚举校验、每个服务端指纹每小时 6 次、`request_id` 幂等；
- `GET https://vip-api.ehs-sil.com/api/admin/feedback`：仅服务端确认的 `admin`，支持状态、类型、工具筛选与分页；
- `GET/PATCH https://vip-api.ehs-sil.com/api/admin/feedback/:id`：仅 `admin`，读取详情并更新处理状态、内部备注、可回复说明与关联版本；
- CORS 只允许正式主站来源，Cookie 写操作沿用 Origin 校验；反馈正文、昵称和联系方式不得进入百度统计或公开日志。

数据库迁移为 `0004_feedback.sql`，新增 `feedback_entries` 与 `feedback_rate_limits`。回滚不删除表：先回退公开入口和脚本，保留已接收记录，再回退 Worker 版本。

## 主理人处理流程

1. 先在 `/dashboard/register.html` 验证管理员权益；
2. 进入 `/dashboard/feedback-admin.html`；
3. 按“已收到”筛选，核对类型、来源和专业影响；
4. 复现或核实后改为“核实中”，记录内部备注；
5. 有明确安排后改为“已安排”；实际修复并验证后才改为“已解决”，填写关联版本和可回复说明；
6. 重复、无法复现或暂不采纳可“已关闭”，但不得计入解决数。

建议每周集中处理两次。法规、培训频次/学时、适用性或风险结论反馈必须先人工核实来源，不由 AI 自动采纳。需要删除或匿名化联系信息时，应在私有数据库中执行并留下不含原文的操作记录。

## 统计口径

百度统计只记录 `feedback_open`、`feedback_submit_success`、`feedback_submit_failed` 及有限枚举上下文。服务端持久化成功数以 D1 中唯一 `request_id` 计算；浏览器超时可能已经写入，因此不能用前端成功事件替代服务端口径。
