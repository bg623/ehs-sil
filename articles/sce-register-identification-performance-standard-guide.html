SCE清单怎么建立？安全关键要素识别、性能标准与验证闭环

一张真正有用的SCE清单，不是从设备台账逐项打勾，而是从重大事故场景出发，找到必须保持有效的关键屏障，再把安全功能映射到可维护、可验证的系统、设备、软件、部件与依赖项。

先说结论：SCE不是“贵重设备”或“所有安全设施”的同义词，也不只是事故前的最后一道防线。清单必须能回答四个问题：它防哪一个重大事故场景、承担什么安全功能、达到什么性能才算有效、靠什么证据持续证明有效。

先把术语边界说清楚

英国海上法规的正式概念是Safety-Critical Elements；在SCR 2015适用的外海油气活动中进一步使用Safety and Environmental-Critical Elements（SECE）。其范围不限于单台设备，还可包括装置结构、系统、设备、计算机程序及其部件：一类是失效可能导致或显著促成重大事故的要素，另一类是用于预防或限制重大事故后果的要素。

本文沿用国内企业常说的“SCE清单”，中文统一表述为安全关键要素；当清单落实到具体位号时，也会出现“安全关键设备”这一管理用语。国内陆上化工企业借鉴的是一种重大事故屏障管理方法，不能把英国海上Safety Case制度直接写成国内普遍法定义务。

与设备完整性的关系：设备完整性管理覆盖设备全生命周期；SCE管理在其中进一步标出与重大事故风险直接相关的要素，并赋予更明确的性能、验证、降级和恢复要求。两者相关，但范围和筛选逻辑不同。

两条识别路径：规范法与风险法

路径怎么做优势主要风险
规范/说明性清单法参考适用法规、设计规范、集团标准或行业清单，建立候选功能与设备范围启动快，便于检查遗漏脱离场景后容易把大量普通设备贴成SCE
风险/场景倒推法从MAH、HAZOP、LOPA、QRA或BowTie出发，识别关键屏障和安全功能，再映射到资产风险锚定清楚，便于解释和合理化依赖高质量场景、跨专业团队和一致判据
推荐的组合方式以风险法确定边界，以规范法做完整性检查和最低要求补充兼顾准确性与完整性必须保留每项纳入或排除的依据

API RP 14C面向海上生产设施安全系统，提供系统分析、安全功能记录、设备识别和测试方法。它可以成为海上油气“规范法”的输入，但不是所有陆上化工企业可直接照抄的通用SCE目录。

6步建立一张可审计的SCE清单

重大事故场景 → 关键屏障/安全功能 → SCE边界 → 性能标准 → 检验维护与验证 → 动态复审
  1. 定义重大事故范围和筛选判据。先约定哪些人员、环境或资产后果属于企业的重大事故范围，以及“导致、显著促成、预防、控制或减缓”如何判断。没有统一判据，不同专业会各自扩大或缩小清单。
  2. 汇总场景，而不是先打开设备台账。从HAZOP、LOPA、QRA、事故情景库和BowTie中汇总重大事故场景，写清危险源、顶事件、后果和现有屏障。风险研究质量不足时，应先补足场景，而不是用清单掩盖分析缺口。
  3. 识别关键屏障和安全功能。逐一判断哪些预防、检测、控制和减缓屏障符合SCE判据。SCE不只包括“最后一道防线”；会引发或显著促成重大事故的关键包容、控制和支撑要素也可能纳入。
  4. 把功能映射到系统与位号边界。从“反应器超压保护”这样的功能名称，下钻到传感器、逻辑处理、最终元件、泄压路径、供电、仪表风、通信和共用取压等依赖。先定义功能边界，再映射位号，可以避免把整套DCS或所有同型号设备一并纳入。
  5. 为每项SCE写可测量的性能标准。常用FARSI五组考虑：功能性（Functionality）、可用性（Availability）、可靠性（Reliability）、存活性（Survivability）、交互与依赖（Interactions and Dependencies）。每项还应写明验收准则、验证方法、频率、责任人和证据位置。
  6. 接入日常管理并设置复审触发。把清单与CMMS中的检验、测试、预防性维护和缺陷工单关联；建立逾期、故障、旁路和降级审批；在MOC、装置变更、事故教训、性能退化、法规或设计依据变化时复审。

SCE清单至少应包含哪些字段

字段组建议内容要回答的问题
风险锚点MAH编号、顶事件、后果、BowTie/LOPA引用为什么它是关键的？
功能与边界屏障功能、SCE系统、设备位号、软件或部件、上下游边界它具体承担什么、范围到哪里？
性能标准动作条件、能力、响应时间、可用性、可靠性、存活性、依赖达到什么程度才算有效？
验证与维护检查/测试方法、周期、验收标准、CMMS任务、证据链接如何证明它现在仍有效？
状态与治理责任人、当前状态、缺陷/旁路、补偿措施、恢复期限、MOC状态失效或变化时谁负责、怎么控制？

反应器超压案例：从场景落到位号

假设某放热反应存在冷却失效导致反应器超压和失去包容的重大事故场景。BowTie可能识别出独立高高压力联锁、紧急冷却或淬灭、泄压装置与安全排放系统等屏障。

建立SCE清单时，不能只写“高压保护”。团队需要确认安全功能及边界：压力检测由哪些变送器完成、表决逻辑位于哪个逻辑解算器、最终动作是关进料阀还是停泵、阀门需要多快关闭、泄压装置排向何处、哪些电源或公用工程是共同依赖。随后为每个功能和组成要素写验收准则、测试方式及降级规则。

注意：BowTie里的每个屏障不自动等于一个SCE。程序、人员响应和组织控制也可作为屏障；SCE清单通常聚焦满足判据的结构、系统、设备、软件与部件。反过来，一个安全功能也可能由多个位号共同实现，不能只挑其中最显眼的一台设备。

怎样给过长的清单“瘦身”

合理化不是为了减少维护成本而删除SCE，而是纠正没有风险依据的泛化。逐项回答：

  1. 能否指向一个明确的重大事故场景和屏障功能？
  2. 失效会导致、显著促成重大事故，还是仅影响产量和一般职业安全？
  3. 是否把一个系统级功能重复拆成大量无差别标签？
  4. 供电、公用工程、软件和共因失效依赖是否遗漏？
  5. 删除或保留的决定是否由跨专业团队批准并留下证据？

若无法说明风险关系，先回到场景和功能边界；若确实不满足SCE判据，可以移出SCE清单，但仍按普通设备完整性或其他适用制度管理。

清单建立后，真正的管理才开始

  • 性能标准：把“应完好”改写为可测试、可判定的技术与运行要求；
  • CMMS连接：让检查、测试、维护和缺陷状态能够追溯到SCE及其场景；
  • 降级管理：SCE失效、旁路或逾期时，重新评价剩余风险、补偿措施和运行边界；
  • 变更管理：修改设备、设定值、软件、维护策略或依赖系统时同步复核SCE；
  • 验证与保证：按适用法规和企业制度采用测试、检查、审计或独立验证，不能把英国海上独立验证制度泛化为所有企业的统一法定义务。

最常见的五个错误

  1. 把重要设备等同SCE：业务关键性与重大事故关键性混在一起；
  2. 从台账向上猜风险：清单很长，却找不到对应场景和安全功能；
  3. 只找最后一道防线：遗漏关键包容、检测、控制、支撑和依赖要素；
  4. 只有位号没有性能标准：无法判定测试是否合格、缺陷是否可接受；
  5. 照搬固定复审周期：忽略MOC、事故、性能退化和法规变化等动态触发。
